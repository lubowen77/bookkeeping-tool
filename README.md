# 记账本 · zhangben

一位个体经营者的**赊账账本**，用来替掉手写的两本纸——「日账本」（每天按笔记）和「人头账本」（按客户归集欠款）。每晚把日账誊抄进人头账本这道工序，是本项目要消灭的东西。

纯本地安卓 App：**无账号、无服务器、无网络依赖**，装上就能用，数据只在这台手机里。

| 项 | 值 |
|---|---|
| 业务性质 | 赊账应收（客户欠款，日后结账） |
| 使用者 | 1 人、1 台安卓手机，零技术门槛 |
| 数据规模 | 客户 300–500 人，单日 ≤ 50 笔 |
| 结账节奏 | 主要集中在年底，少量随时零散结账 |
| 当前版本 | v1.6（`1.6.0+6`），minSdk 26 / Android 8.0+ |

设计总原则：**使用者零技术门槛，维护者零服务器负担。**

## 核心业务规则

### 余额模型

流水（entry）只有 4 种类型，客户余额是它们的**派生值**，不存字段、不允许手工改：

```
余额 = Σinitial + Σdebt − Σpayment − Σdiscount     （仅计未作废流水）
```

| kind | 界面显示 | 方向 | 含义 |
|---|---|---|---|
| `initial` | 期初旧账 | + | 上线时从纸本迁入的历史欠款 |
| `debt` | 记账 | + | 日常的「业务 + 金额」 |
| `payment` | 收款 | − | 客户还钱，支持部分还款 |
| `discount` | 抹零 | − | 结账时的减免 |

改余额的唯一途径是增改流水。余额可为负（多付/预存），界面显示「多付 ¥X」。

### 几条不能动的约定

- **金额一律以「分」存整数**（`amount_cents`），恒为正，方向由 `kind` 决定；
- **业务名是文本快照**：流水上的 `business` 是记账当时的业务名。业务日后改名或删除，**不回溯**修改任何历史流水——账本当时写的是什么就是什么。`businesses` 表只是输入辅助字典，不与 `entries` 建外键；
- **一切删除都是软删除**（`deleted_at` 标记），进回收站可恢复，回收站不自动清空；
- **业务日期与录入时间分离**（`biz_date` / `created_at`），晚间补录、漏记补记靠这个；
- 一次结账产生的「收款 + 抹零」两条流水，事后编辑删除**互相独立、不做联动**——余额公式对任何单条改动都自洽。

### 数据表

SQLite（drift），5 张表：`customers` / `entries` / `settings` / `day_photos` / `businesses`。完整 DDL 见方案文档 §4。

## 备份与迁移

可靠性是核心，优先级与记账同级。没有云端，备份就是全部保障。

- **格式**：单个 JSON 文件，自定义扩展名 `.jzb`，带 SHA-256 校验与 `schema_version`；文件名形如 `记账备份-20260807-2130.jzb`；
- **自动备份**：每日首次启动时生成，双写 App 私有目录 + 公共 `Download/记账备份/`（卸载不丢），保留最近 60 份；
- **外发**：「发送备份给家人」→ 生成最新备份 → 调系统分享面板 → 使用者自己选微信发送。安卓不允许 App 静默代发微信，**这一步必须人点，是平台限制不是缺陷**；
- **分轨**：账目数据（几百 KB）与纸本照片**永远分开备份**。外发默认只发数据文件，照片走独立的 zip 导出，仅换机时手动使用；
- **恢复**：App 注册 `.jzb` 文件关联。微信收到 → 点开 → 选「记账本」→ 校验 checksum → 显示摘要（「412 位客户、9873 笔账，备份于 8 月 7 日」）→ 确认导入。**导入 = 全量替换**，导入前自动把当前库先备份一份防手滑。

## 适老化 UI 硬性要求

不是风格偏好，是验收标准：

- 正文 ≥18sp，列表主文字 20sp，金额 22sp，客户详情余额 40sp；字体三档（标准 / 大 ×1.15 / 特大 ×1.3）全局缩放；
- 触控目标 ≥48dp，主操作按钮高 ≥56dp；
- 图标必须带文字标签，**无纯图标按钮**；不依赖滑动手势作为任何功能的唯一入口；
- 浅色主题，高对比，**不做深色模式**（刻意决策，降认知负担）；
- 用账本口语，禁止系统腔：说「记一笔 / 欠款 / 收款 / 抹零 / 结清 / 期初旧账 / 回收站」，不说「新建条目 / 应收账款 / 事务 / 同步」；
- **全 App 禁用「赊」字**——使用者和客户的语言习惯如此，且这个字出现在发给客户的账单上观感不佳；
- **强制中文本地化**：`locale: Locale('zh','CN')` 不跟随系统语言，日期选择器等系统组件弹层必须是中文（v1 真机实测踩过的坑）；
- 所有金额数字 `tabular-nums` 等宽对齐。

## 技术栈

Flutter (Dart) + drift(SQLite)，打包原生 APK。

```
lib/
├── app/        应用壳、主题、全局控制器
├── core/       金额、时间、拼音等纯函数工具
├── data/       数据层
│   ├── database/     drift 表定义与迁移
│   ├── repositories/ 仓储（业务规则的落点）
│   ├── backup/       备份导出、导入、校验
│   ├── billing/      客户账单长图生成
│   └── photos/       按天纸本照片
├── domain/     领域模型
└── ui/         页面：记一笔 / 今天 / 客户 / 我的
```

选 Flutter 而不是 Web 容器的理由：国产安卓 WebView 版本碎片化，是目标人群旧手机上的真实风险；SQLite、文件分享、intent-filter 文件关联、MediaStore 写入都有成熟一等插件。

工程约束：

- 权限最小化，**禁止引入任何统计 / 推送 / 广告 SDK**；
- `minSdkVersion 26`（Android 8.0，覆盖目标人群旧手机）；
- APK 直装分发，不上架商店，避免年审负担。

## 本地开发

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # 生成 drift 代码
flutter test
flutter run
```

出正式包：

```bash
flutter build apk --release
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`。

> **发布签名密钥不在本仓库内**（已被 `.gitignore` 排除，仅存于开发机 `android/keystore/`）。密钥丢失 = 永远无法向已安装设备推送升级，只能卸载重装。务必在别处离机备份。

国内网络首次拉依赖前建议设镜像：

```bash
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

## 明确不做

未经确认，任何版本都不得加入：

- ❌ 云端同步、账号体系、任何后端服务
- ❌ 手写账本 OCR 识别
- ❌ 多用户、多设备实时同步
- ❌ 打印
- ❌ 深色模式

后续版本已规划但本期不做（架构不得阻碍）：v2 语音条速记（白天按住说一句，晚间回放补录）、v3 语音 AI 转写预填。
